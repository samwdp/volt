# DAP: one Session per Workspace, custom client, system Debug Layout

Debugging follows the LSP host pattern: typed protocol (`dap-types`) plus a Volt-owned client in `editor-dap`, not a third-party session manager (`vix-dap` / `dscode-dap`). Each Workspace owns at most one Debug Session; switching Workspaces hides the Debug Layout but keeps the Session running. While the Debug Layout is active, user-created splits are blocked and golden-ratio sizing is forced off (same override idea as Database Multiview); Debug Stop restores the prior layout. Adapter specs mirror Language Server Specs (identity, roots, priority, stdio/TCP transport); launch/attach bodies and compile-before-debug live in the configuration/infer layer. One Debug Stop command ends the Session (kill debugee after launch, leave process after attach)—no separate detach.
